# MediaViewer Android 整体界面系统与流程加固设计

日期：2026-07-31

状态：对话方案已确认，待用户审阅文档

适用范围：Android 应用整体界面、共享原生组件、音视频与图片媒体界面，以及直接影响主流程可用性的状态与恢复逻辑

## 1. 背景

播放器恢复、时间轴、竖向音量、后台声音和播放队列的上一轮专项改造已经完成。当前应用已具备首页、服务器设置、共享目录浏览、图片阅读、音视频播放、迷你播放器和持久播放队列，但整体界面仍存在两类问题：

1. 首页、浏览器和设置页主要直接使用默认 Material 3 组件，播放器则使用独立的霓虹青紫视觉语言，缺少统一的产品外观。
2. 页面壳层、加载/空/错误状态、返回行为和冷恢复流程没有统一模型，部分问题会导致内容被遮挡、永久等待或错误操作。

本次选择“媒体化 Material 3 混合设计”：保留 Material 3 的平台语义、触摸目标、焦点、无障碍和弹层行为，在其上建立 MediaViewer 的设计令牌和媒体界面组件。播放器和图片阅读器可使用更沉浸的皮肤，但不全量自绘基础控件。

项目用于个人使用。本次不引入账号体系、复杂鉴权、遥测平台、远程配置或重量级审批逻辑。

## 2. 已确认的产品决策

- 采用推荐方案 A：媒体化 Material 3 混合设计。
- 音频、视频和共享播放控件同时统一；视频专属手势不进入音频页。
- 图标继续使用已确认的霓虹双色方向，并扩展到仍缺失的媒体操作、导航、文件类型和状态图标。
- 播放队列采用“A：分层紧凑列表”。
- 普通模式音量使用锚定竖向浮层；全屏使用临时竖向反馈轨。
- 视频进入后台后继续播放声音，画面停在离开前的帧；回前台恢复当前播放位置的画面。
- 暂停后拖动时间轴，松手仍保持暂停并显示目标帧；再次播放从目标位置恢复。
- 播放页只保留一条主时间轴，不恢复其下方的独立加载进度条。
- 保留手动加入队列、插入下一项、调整顺序、删除队列项和跨重启恢复。
- 使用业内常见的加载、错误、返回、队列和后台恢复处理方式，但保持个人项目所需的简单确认逻辑。
- 完成后仍按正常流程生成仅包含 `arm64-v8a` 的个人签名 Release APK。

## 3. 目标与非目标

### 3.1 目标

1. 建立统一的颜色、排版、形状、间距、层级、动效和播放器令牌。
2. 美化并统一高频原生组件，同时保留 Material 3 的交互语义。
3. 让应用壳层正确处理系统栏、键盘、迷你播放器、Snackbar 和内容安全区。
4. 重新设计首页、目录浏览、设置、图片阅读、音频、视频、迷你播放器和播放队列。
5. 统一首次加载、刷新、局部加载、空状态、离线、错误和自动恢复反馈。
6. 修复审计发现的 P0/P1 主流程问题，并形成可重复执行的 Bug 排查矩阵。
7. 覆盖浅色、深色、小屏、横屏、大字体、系统返回和 API 29–36 的关键适配。
8. 保持已通过的后台播放、进度同步、Surface 恢复和队列持久化行为。

### 3.2 非目标

- 不增加字幕、多音轨、投屏、画中画、清晰度切换或在线媒体搜索。
- 不增加登录、权限角色、复杂服务器认证或多服务器工作区。
- 不增加底部主导航；当前只有一个稳定顶层入口。
- 不为了“界面丰富”增加收藏、历史、标签、批量管理或文件删除。
- 不替换 LibVLC、Media3、Room、DataStore 或现有导航框架。
- 不引入自定义字体下载、重型动画框架或全面自绘基础控件。
- 不把自动化结果等同于未执行的真机、真实服务器或人工视觉验收。

## 4. 设计原则

### 4.1 内容优先

- 目录名、文件名、当前媒体和播放状态是首要信息。
- 装饰性渐变、发光和容器只用于建立层级，不能降低文字、图标或画面可读性。
- 普通页面保持高信息密度；播放器和图片页可以沉浸，但核心操作始终可发现。

### 4.2 原生行为优先

- Button、TextField、Dialog、BottomSheet、Menu、Slider、Snackbar 等继续建立在 Material 3 组件之上。
- 只包装具有跨页面产品语义或容易不一致的组件，不为每个 Material API 机械增加一层。
- 保留 Android 的返回、焦点、键盘、TalkBack 和最小触摸目标行为。

### 4.3 状态必须可恢复

- 无限加载不能成为最终状态。
- 阻断错误必须提供一个主恢复动作和一个安全离开动作。
- 自动恢复保留已有内容并使用非阻断反馈，不能无故清空页面。
- 重试当前媒体不能重建整个队列、重置倍速或跳到下一项掩盖错误。

### 4.4 个人使用保持克制

- 普通待播项删除不确认，并提供短时撤销；删除当前播放项、清空全部等明显破坏播放上下文的操作才确认。
- 不为本地个人服务器增加企业级审查、复杂验证或多步向导。
- 不添加与网络浏览和媒体播放无关的运行时权限。

## 5. 信息架构与应用壳层

### 5.1 页面层级

应用保持以下层级，不增加底部 NavigationBar：

```text
首页
├─ 服务器设置
├─ 共享目录浏览
│  ├─ 子目录
│  ├─ 图片阅读器
│  └─ 音频/视频播放器
└─ 当前播放入口
   ├─ 迷你播放器
   ├─ 播放器
   └─ 播放队列浮层
```

设置、浏览、图片和播放器均属于层级内页面。将来只有在出现至少三个稳定平级入口时，才评估自适应底栏或导航轨。

### 5.2 统一壳层

建立两个共享壳层：

- `MediaAppScaffold`
  - 位于 `MediaViewerApp` 根部。
  - 负责 NavHost、全局 Snackbar、迷你播放器 bottom bar、系统栏和导航栏 inset。
  - 迷你播放器占用实际布局空间，不再用根 `Box` 绝对覆盖页面。
- `MediaScreenScaffold`
  - 负责页面 TopAppBar、背景、滚动行为、内容安全区和可选状态横幅。
  - 首页、浏览器和设置使用同一壳层。
  - 图片和全屏视频使用沉浸变体，但仍消费安全区。

页面接收 Scaffold 提供的 content padding；列表额外叠加自身节奏间距，不能硬编码迷你播放器高度。

现有未被使用的 `MediaRouteShell` 不继续保留第二套壳层：实施时将其能力合并进 `MediaScreenScaffold` 并删除旧文件，或在第一批迁移中直接将其改造成唯一的 `MediaScreenScaffold`，两者只能保留一个公共入口。

Manifest/资源主题同步提供与 Compose 明暗背景一致的启动窗口和系统栏颜色，避免冷启动先闪出平台默认 Material 主题。应用进入 Compose 后统一使用 edge-to-edge 和安全区策略。

- `surface0`：页面 background。
- `surface1`：普通列表/卡片，0dp tonal elevation。
- `surface2`：选中列表、状态卡，1dp tonal elevation。
- `surface3`：迷你播放器、菜单，3dp tonal elevation。
- `surface4`：Sheet 和 Dialog，6dp tonal elevation。

视频黑底使用单独的 `PlayerColors`，不直接复用普通页面亮色：

- `canvas = #000000`

- `accent = #C9BFFF`
- `disabled = #7D878F`，并配合 60% 透明度和 disabled 语义

- `unplayedTrack = #59636D`，55% 透明度

- `bottomScrim = #00000000 → #CC000000`

要求：

- 普通页面不得直接使用播放器亮青色硬编码。
- 视频黑底可以使用高亮青紫色；浅色页面使用更深的品牌色。
- 当前项、错误、禁用等状态不能只依赖颜色，还要配合图标、文本、边框或透明度。
- 普通文字对背景至少 4.5:1；大字、图标、时间轴和关键非文字控制至少 3:1。实施时用工具计算，不靠目测。

### 6.2 排版

继续使用系统字体，避免新增字体包。定义以下语义角色：

- `appTitle`：应用品牌标题。
- `screenTitle`：页面标题。
- `sectionTitle`：设置和内容分区标题。
- `body`：主要正文。
- `metadata`：路径、类型、时长、IP 等次级信息。
- `badge`：连接、当前项、下一项和模式标签。
- `playerTime`：时间轴时间，使用等宽数字特性或稳定宽度容器。

映射到 Material Typography：

| 语义角色 | Material 角色 | 最大行数/溢出 |
|---|---|---|
| appTitle | `titleLarge` | 1 行，ellipsis |
| screenTitle | `titleLarge` | 1 行，ellipsis |
| sectionTitle | `titleMedium` | 2 行 |
| body | `bodyLarge` | 由内容决定 |
| metadata | `bodySmall` | 列表内 1 行，ellipsis |
| badge | `labelMedium` | 1 行 |
| playerTime | `labelLarge` | 固定 `00:00:00` 最大宽度或等宽数字 |

中文文本保持足够行高；文件名在列表中最多 2 行，播放器标题普通模式最多 2 行、全屏最多 1 行。2.0 倍字体下允许标题省略或换行，但主操作不得被挤出屏幕。

### 6.3 形状、间距与层级

- 形状：`small = 8dp`、`medium = 12dp`、`large = 16dp`、`extraLarge = 24dp`、`pill = 50%`。
- 间距：4、8、12、16、20、24、32dp 七档。
- 手机页面水平 gutter 为 16dp，宽度 ≥600dp 时为 24dp；卡片内边距 16dp；紧凑列表项内容间距 12dp。
- 触摸目标：视觉图标可为 20–28dp，实际点击区至少 48dp。
- 普通图标/传输按钮点击区 48dp，主播放按钮 64dp，全屏主播放按钮 72dp。
- 主时间轴可见轨道 4dp、thumb 18dp，整体触摸高度至少 48dp。
- 竖向音量/亮度可见轨道 4dp，触摸区至少 48×160dp；普通音量浮层约 72×224dp。
- 迷你播放器目标高度 72dp，顶部实际位置轨 2dp。
- 文件行和队列行最小高度 64dp；内容需要换行时允许自然增高。
- 页面卡片最多使用上述五级 surface/tonal elevation，禁止页面自行硬编码阴影。
- 视频控制层使用渐变 scrim，不使用覆盖大面积内容的实色工具栏。

### 6.4 动效

- 按压和选中：120ms，`LinearOutSlowInEasing`。
- 普通展开/收起和页面状态切换：180ms，`FastOutSlowInEasing`。
- Sheet、Dialog、全屏控制层和队列位置变化：240ms，`FastOutSlowInEasing`。
- 队列拖动开始时提升到 `surface4`、轻微缩放至 1.02 并触发一次触觉反馈；释放后在 180ms 内回落。动画不改变最终索引计算。
- 全屏控制层在无菜单、无拖动、未锁定且处于播放/缓冲状态时，沿用现有 3 秒自动隐藏；任何有效控制交互重置计时。暂停、Opening、Error 时保持可见。
- 音量和亮度反馈在手势结束后沿用现有约 800ms 延迟，再用 180ms 淡出。
- 缓冲动画只由真实缓冲状态驱动。
- 尊重系统动画缩放设置，不让动效成为理解操作的唯一方式。

### 6.5 图标

- 媒体操作统一走 `PlayerIcons`/共享媒体图标入口。
- 补齐返回、全屏、队列、文件类型、连接、离线、空状态和错误图标的视觉容器与 tint 规则。
- 导航类可以使用 Material 图形，但线宽、容器、颜色和触摸区必须统一。
- 不使用固定分辨率位图作为控件图标；使用 VectorDrawable 或 Compose `ImageVector`。
- 所有可操作图标提供准确 `contentDescription`，列表菜单描述中包含目标文件名。

## 7. 原生组件美化边界

### 7.1 必须建立共享语义组件

| 组件 | 输入与状态 | 负责 | 不负责 |
|---|---|---|---|
| `MediaTopAppBar` | 标题、导航动作、actions、scroll behavior | 标题层级、按钮容器、省略、inset | 导航决策 |
| `MediaStatePanel` | Loading/Empty/Offline/Error、标题、说明、主次动作 | 图标、布局、操作层级、live region | 发起网络请求 |
| `MediaPrimaryButton` / `MediaSecondaryButton` / `MediaDestructiveButton` | 文案、图标、enabled、loading、回调 | 高度、圆角、进度、危险色 | 业务校验 |
| `MediaIconButton` / `PlayerIconButton` | 图标、描述、enabled、selected、loading、回调 | 48dp 触摸区、状态、tooltip、颜色 | 推导播放器状态 |
| `MediaUrlField` | value、validation、Testing/Success/Error、IME 回调 | 协议键盘、清除、supporting text、字段语义 | 探测或保存服务器 |
| `MediaConfirmDialog` | 标题、说明、Normal/Destructive、确认/取消 | 按钮顺序、危险色、焦点、返回/外部点击 | 执行业务删除 |
| `MediaBottomSheet` | 标题、内容、关闭回调、可选 actions | drag handle、最大高度、滚动边界、inset | 持有队列 |
| `MediaOptionMenu` | 选项、选中 key、选择/关闭回调 | 图标、勾选、宽度、焦点和关闭语义 | 解释业务值 |
| `MediaTimelineSlider` | duration、displayPosition、enabled、drag/commit 回调 | 单一轨道、thumb、预览标签、adjustable 语义 | 自行推进时间或直接 seek 引擎 |
| `MediaVerticalLevelControl` | 0–1 value、静音/锁定状态、调整回调 | 真正竖向手势、百分比、adjustable 语义 | 直接访问 Activity 或 AudioManager |
| `MediaSnackbarHost` | 成功/错误消息、action、bottom bar 状态 | 图标、动作样式、迷你播放器避让 | 决定何时产生事件 |

### 7.2 页面语义组件

| 组件 | 输入 | 状态/回调边界 |
|---|---|---|
| `ConnectionStatusCard` | 会话展示状态、地址、IP、错误摘要 | 仅发出重试/设置回调 |
| `ShareCard` | 名称、可浏览性、不可用原因 | 仅在可浏览时发出打开回调 |
| `MediaBreadcrumbs` | 稳定路径段和当前段 | 发出目标层级回调，不自行导航 |
| `MediaFileRow` | mediaKey、名称、类型、元数据、可用动作 | 发出打开/菜单回调，不读取文件系统 |
| `SettingsSection` / `SingleChoiceSetting` | 标题、说明、选项、选中 key | 发出选择回调，不持久化偏好 |
| `AudioArtworkPlaceholder` | 文件类型和可选首字/图标 | 只渲染本地占位，不联网取封面 |
| `NowPlayingBar` | 当前项、主动作映射、进度、canSkipNext | 发出打开/播放/暂停/下一项/队列回调 |
| `PlaybackQueueItem` | 稳定 mediaKey、标题、当前/下一状态、拖动状态 | 发出选择/拖动/删除/无障碍移动回调 |
| `PlayerStateOverlay` | Opening/Buffering/Error 与操作 | 只覆盖媒体状态层，不拥有控制器 |

播放器共享组件使用唯一的主动作映射：

| 播放状态 | 主动作 | 图标/反馈 |
|---|---|---|
| `PLAYING` | 暂停 | 暂停图标 |
| `BUFFERING` | 暂停 | 暂停图标 + 小型缓冲环 |
| `IDLE` / `PAUSED` | 播放 | 播放图标 |
| `ENDED` | 重播 | 重播图标 |
| `OPENING` | 禁用 | 打开中反馈 |
| `ERROR` | 无主传输动作 | 由 `PlayerStateOverlay` 提供重试 |

表中的状态只指真实 `PlaybackStatus`；它与 11.2 的 `PlayerEntryState.Ready` 是两个不同层级，禁止混用。普通播放器、全屏播放器和迷你播放器必须复用同一纯映射函数，并覆盖 `IDLE` 的图标、描述、enabled 和回调测试。

`PlayerStateOverlay` 只负责 Opening/Buffering/Error 的媒体区域反馈，不覆盖返回、暂停和时间轴；`PlayerOptionMenu` 只统一菜单外观、选择标记和关闭行为，倍速、比例、模式继续使用各自的业务枚举。`NowPlayingBar` 只消费窄化的播放展示模型和回调，不拥有播放引擎；`PlaybackQueueItem` 只呈现稳定 `mediaKey` 对应的状态和手势，排序/持久化仍属于队列层。

按钮与弹层规则：

- 一个页面或一个阻断弹层最多只有一个高强调主动作。
- loading 按钮保留原宽度并禁止重复点击；disabled 状态仍提供可理解的视觉和语义。
- 信息 Dialog 允许返回键和外部点击关闭；普通/危险确认 Dialog 只允许明确“取消”或“确认”关闭，防止误触。
- Sheet、Dialog 打开后焦点约束在浮层内，关闭后回到触发控件。
- 普通模式音量浮层在点击外部、按返回或 3 秒无操作后关闭；滑动、静音和系统音量更新会重置无操作计时。

动态无障碍状态契约：

- `enabled = false` 使用标准 disabled 语义；loading 状态同时 disabled，并提供“正在连接/正在保存/正在打开”等 `stateDescription`。
- 单选项和当前队列项使用标准 selected 语义；播放模式循环按钮使用 `stateDescription = 顺序播放/单曲循环/随机播放`。
- 静音按钮使用可切换语义，`stateDescription = 已静音/未静音，音量 N%`；竖向音量轨继续提供标准 adjustable/range 语义。
- 全屏锁定按钮使用可切换语义，`stateDescription = 控制已锁定/控制未锁定`。
- Buffering 的主动作仍为“暂停”，并提供 `stateDescription = 正在缓冲，可暂停`；不能只靠旋转环表达。
- 队列当前项使用 selected 语义并提供“正在播放”；下一项提供“即将播放”；普通项不设置这两个状态。
- 父级已经通过 `stateDescription` 表达状态时，纯装饰的可见 badge/icon 不再单独进入无障碍树，避免重复播报；文件名、动作和必要元数据仍合并为一次可理解的行描述。

### 7.3 不建立无意义包装

- 单次使用且只依赖主题的 `Text`、`Spacer`、`Divider`、`Box`、`Row` 和 `Column` 直接使用 Compose API。
- 只改变一个颜色或一个 padding 的 Material 组件不单独包装。
- 共享组件不得读取 ViewModel 或 Repository；业务状态和动作由页面传入。
- 通用组件不得依赖 `PlayerUiState`、Activity、导航控制器或网络会话；播放器专用组件只接收窄化后的展示模型。

## 8. 页面设计

### 8.1 首页

结构：

1. 顶栏显示 MediaViewer 标题和设置入口。
2. 首屏显示连接状态卡：
   - 连接中：短文案和小型进度。
   - 已连接：成功图标、服务器地址，IPv4 作为次级信息。
   - 失败：原因摘要、重试主操作、设置次操作。
3. 共享使用 `LazyColumn` 的紧凑卡片/列表。
4. 每个共享显示文件夹图标、名称、状态说明和进入箭头：
   - 可浏览共享正常可点。
   - 服务器关闭目录浏览时显示“目录浏览未开放”并禁用。
   - Basic Auth 等当前不支持的共享显示“不支持当前认证方式”并禁用。
   - 禁用项降低容器强调并移除进入箭头，不能仍表现为可点击。
5. 无共享时使用统一空状态，并提供设置或重试。

首页不显示调试式逐行 IP 信息，不增加最近播放、收藏或推荐内容。

### 8.2 目录浏览

- 顶栏显示当前共享或目录名，提供返回和一个刷新入口。
- 面包屑可横向滚动，使用根图标、分隔符和当前层级强调；长名称省略。
- 文件列表采用分层紧凑行：
  - 图标底座区分目录、图片、视频、音频和未知文件。
  - 主行显示名称，副行显示类型或必要元数据。
  - 菜单点击区独立，内容描述包含文件名。
- 媒体菜单顺序固定为“立即播放”“下一项播放”“加入队列”。
- 首次加载使用状态面板；已有内容刷新时保留列表并显示非阻断进度。
- 子目录加载失败时保留父目录和返回语境。
- 空目录显示上下文空状态，不隐藏面包屑。

### 8.3 设置

- 页面使用 `LazyColumn` 或 `verticalScroll`，消费 `imePadding` 和导航栏 inset。
- 服务器区：
  - `MediaUrlField` 展示输入、校验、连接测试和结果。
  - “保存”为主操作；“测试连接”为次操作。
  - 保存和测试都有按钮内进度，失败后留在当前页并可重试。
- 图片阅读区：
  - 使用单选设置行或可换行选择控件。
  - 每个模式带一句简短行为说明。
- 已验证但未保存的变更在返回时使用轻量放弃确认；普通未验证输入无需复杂拦截。
- 测试或保存进行中离页时取消请求或忽略迟到 generation；旧结果不能覆盖新输入。
- 测试得到的 IPv4 只作为“将连接到 …”结果展示，当前没有人工选择能力时不得伪装成单选列表。

### 8.4 图片阅读器

- 图片内容保持全屏优先，默认使用深色沉浸背景。
- 轻触切换顶部工具栏；返回、文件名、当前序号和模式入口保持可用。
- 工具栏使用渐变 scrim，并消费刘海和导航手势 inset。
- 单图模式保留缩放、平移和切换；条漫模式保留连续列表和位置恢复。
- 单项解码失败只替换当前图片为错误面板，不清空整个序列。
- 网络自动恢复使用非阻断提示；人工重试必须能重新建立端点，不只是重复旧 URL。
- 不增加编辑、删除、分享或图片元数据面板。
- 图片阅读器纳入本轮整体视觉统一，但不重写缩放、条漫加载、排序和阅读位置等内部交互；任何新交互需另立规格。

### 8.5 音频播放器

- 使用主题化封面占位、文件名和必要媒体信息，减少大图标加空白背景。
- 主传输控制与视频保持相同图标、尺寸、状态和时间轴。
- 倍速、模式和队列入口保持可见；视频比例和全屏手势不出现。
- 锚定竖向音量浮层点击入口只展开，不切换静音；底部独立静音按钮。
- Opening、Buffering、Error 使用共享播放器状态语义。

### 8.6 视频播放器

普通模式：

- 视频区域保持内容优先，中心主控制和缓冲反馈使用独立槽位，不靠固定负偏移避让。
- 只保留一条主时间轴；拖动显示目标时间，当前/总时长左右分置。
- 次级操作按频率分组，小屏时低频选项进入统一菜单。

全屏模式：

- 上下控制层改为渐变 scrim，并消费 `safeDrawingInsets`。
- 返回、标题、队列入口真实可用；不再显示“即将支持”。
- 低频画面比例、倍速和模式进入统一选项面板，避免横屏窄高度拥挤。
- 左侧上下滑动调节当前窗口亮度，右侧调节系统媒体音量；反馈轨临时显示。
- 锁定时禁用进度、音量和亮度手势，只保留明确解锁入口。
- 关闭首次手势提示只关闭提示，不退出全屏。

### 8.7 迷你播放器

- 作为 `MediaAppScaffold.bottomBar` 占用布局空间。
- 显示媒体类型/缩略占位、标题、主播放动作和下一项。
- 顶部可显示 2dp 的实际播放位置轨；它不是缓冲进度条。
- `PLAYING` 和 `BUFFERING` 均保留可暂停语义，Buffering 额外显示小型状态环。
- 无下一项时禁用下一项动作；点击主体打开当前播放器。
- 常规宽度显示播放/暂停、下一项和队列；宽度低于 360dp 或 2.0 倍字体下保留播放/暂停与队列，将“下一项”留在完整播放器/队列中，保证标题和触摸区不互相覆盖。
- 队列为空时自动移除迷你播放器。

### 8.8 播放队列

- 使用可用窗口高度的比例，不固定死 480dp；消费导航栏 inset。
- 顶部显示“播放队列”、项目数量和当前模式，危险动作进入更多菜单。
- 队列项采用已确认的分层紧凑布局：
  - 当前项：主色边线、播放标识和“正在播放”。
  - 下一项：次级标签“即将播放”。
  - 普通项：低层级 surface。
- 显示拖动把手；一次拖动可跨多项并自动滚动。
- 普通滚动从内容区域开始，排序从拖动把手长按开始，避免误触；拖动过程始终按稳定 `mediaKey` 定位。
- TalkBack 保留“上移”“下移”“删除”自定义动作，并在移动完成后播报新位置。
- 点击切换播放，普通待播项删除后提供撤销 Snackbar。
- 删除当前项和停止清空全部保留简短确认。
- “清空其他”在只有当前项时禁用；随机模式只改变播放遍历顺序，不重排用户看到的持久队列。
- 空队列显示空状态并可关闭浮层或返回浏览器添加。
- Room 持久化失败必须有可见反馈，不能声称已经保存。

## 9. 统一状态与反馈

### 9.1 五类加载层级

| 层级 | 呈现 | 旧内容 |
|---|---|---|
| 首次加载 | 居中状态面板或内容骨架 | 无 |
| 刷新 | 顶栏或列表内非阻断进度 | 保留 |
| 局部加载 | 图片项、按钮或播放器区域内反馈 | 保留 |
| 自动恢复 | 横幅、Snackbar 或轻量状态 Chip | 保留 |
| 阻断错误 | 错误面板 + 主恢复动作 + 安全离开 | 无可用内容时替换 |

短于约 250ms 的加载不强制显示大型 spinner，避免闪烁。播放器短缓冲只显示局部反馈；连续缓冲约 8–10 秒后再升级为慢网络提示。

### 9.2 错误分类

- 服务器不可达：重试、打开设置。
- HTTP/目录错误：重试当前目录、返回父目录。
- 图片加载/解码错误：重试当前项、继续浏览其他图片。
- 播放服务连接失败：重连播放器、返回来源页。
- 媒体打开/解码失败：重试当前媒体、返回；不自动跳项掩盖错误。
- 队列持久化失败：保持当前内存操作并明确“尚未保存”，允许重试。

### 9.3 Snackbar

- 成功：加入队列、普通删除撤销、设置保存。
- 错误：后台持久化失败、非阻断刷新失败。
- Snackbar 必须避让迷你播放器和系统导航栏。
- 阻断错误不用 Snackbar 代替页面级错误状态。

## 10. 返回、弹层和窗口行为

返回优先级固定为：

1. 关闭菜单、音量浮层和信息/确认对话框。
2. 关闭播放队列 Bottom Sheet。
3. 视频锁定时提示解锁；未锁定全屏时退出全屏。
4. 浏览器返回上一目录层级。
5. 图片/播放器返回来源目录。
6. 设置存在已验证但未保存变更时确认放弃。
7. 首页退出应用。

要求：

- 顶栏返回和系统返回结果一致。
- 覆盖 Android 预测返回。
- 横竖屏、小窗和 2.0 倍字体下主操作可达。
- 不在本轮贸然移除 Activity 的 `configChanges`；先补 Activity 重建、进程恢复和服务存活测试。
- 基础 RTL 布局使用 start/end 自动镜像；返回、进入等导航图标使用 AutoMirrored 版本。媒体播放时间从左到右、进度方向和 ±10 秒含义不随 RTL 反转。

## 11. 主流程逻辑加固

### 11.1 应用级服务器连接启动

现状中 `connectSaved()` 由 `HomeViewModel.init` 触发，冷恢复到 Browser 或 ImageReader 时可能没有任何对象发起连接。

设计：

- 在应用容器或根导航层建立幂等的连接启动协调器。
- 应用可用后只负责触发一次“读取已保存配置并连接”；首页只观察状态和提供人工重试。
- 多页面同时请求连接时复用同一 `ServerSessionManager` 状态，不并发启动重复探测。
- 没有保存配置时进入明确的“需要设置服务器”状态，不无限 Connecting。

### 11.2 Player Bootstrap 状态

建立显式状态：

- `Connecting`：控制器/服务连接中。
- `Ready`：已有当前项，可进入音频或视频页。
- `Empty`：队列为空，提供返回浏览器。
- `Failed`：服务或控制器启动失败，提供重连和返回。

路由不得在 `currentItem == null` 时直接返回空白 Composable。通知冷启动时先展示可见恢复页，再根据服务队列打开当前媒体。

### 11.3 目录失败与离线保留

- 打开子目录前记录“当前已展示目录”和“正在尝试目录”，请求成功后才提交为当前层级。
- 子目录失败后保持父目录内容和返回栈。
- 已有列表刷新失败时保留旧内容，显示“当前内容可能不是最新”。
- 页面重连不能让 Browser 的标题、返回和旧内容全部消失。

### 11.4 设置保存

- `SettingsViewModel` 显式建模 `isSaving`、`saveError` 和一次性成功事件。
- 保存失败留在设置页，按钮恢复可点击并显示错误。
- 测试中修改地址会使旧测试结果失效；未通过测试的地址不能伪装成已保存有效配置。

### 11.5 图片人工恢复

- 自动端点刷新仍限制为一次，避免请求风暴。
- 用户明确点击重试时可以再次请求会话刷新并构造新实际 URL。
- 已成功图片不重载；失败图片按新的请求代数重试。

### 11.6 队列反馈和来源导航

- 队列 Repository 的持久化失败映射到 UI 可消费的非阻断错误事件。
- 普通删除支持撤销，恢复原索引。
- 播放器来源至少区分应用内目录导航和通知冷启动。
- 队列清空后：应用内播放器返回原导航栈；通知冷启动则回首页，不能进入永久 Waiting。

## 12. 数据流与代码边界

```text
Repository / Service / Media3
          ↓
ViewModel / 状态机 / 协调器
          ↓
Screen state + one-shot UI events
          ↓
共享 Media 组件
          ↓
Material 3 / 自定义媒体绘制
```

约束：

- 主题和组件层不访问 Repository、MediaController 或导航控制器。
- ViewModel 不持有 Compose 类型。
- 业务错误先映射为稳定状态或 UI 事件，再由共享状态组件展示。
- 不引入新的依赖注入框架；继续通过 `AppContainer` 组合依赖。
- 视觉改造不能改变稳定 `mediaKey`、逻辑 URL、队列身份或 Room schema，除非某个已批准的 Bug 修复确实需要迁移。
- 测试 tag 和无障碍语义是对外契约；行为变更时先更新测试，再更新实现。

## 14. 测试与验收

### 14.1 状态与逻辑

- 无保存配置启动不会无限连接。
- 冷恢复 Browser、ImageReader 和 Player 都有可见、可恢复状态。
- Player 控制器失败和空队列不会显示空白页面。
- 子目录失败返回父目录，不退出共享。
- 设置保存失败留页并可重试。
- 图片第二次人工重试会刷新端点。
- 队列持久化失败有可见反馈。

### 14.2 Compose 与交互

- 先修正陈旧的 `PlayerScreenTest` 音量契约：入口只展开、节点使用竖向音量语义/新 tag，静音由独立动作验证。
- 共享组件测试覆盖按钮、URL 输入、状态面板、Dialog、Sheet、时间轴、竖向调节和播放器图标按钮的关键状态。
- 迷你播放器出现时首页和目录最后一项仍可滚动、点击。
- Buffering 时普通、全屏和迷你播放器主动作语义一致。
- 普通、全屏和迷你播放器在 `IDLE` 下均显示可用的播放动作并触发同一回调语义。
- 全屏队列可打开；关闭手势帮助不退出全屏。
- 普通音量入口只打开竖向浮层，独立静音。
- 队列可跨多项拖动、删除、撤销并保留当前项。
- 弹层和返回严格遵循优先级。
- Compose 语义断言覆盖：播放模式 stateDescription、静音 toggle/stateDescription、全屏锁定 toggle/stateDescription、Buffering 主动作“正在缓冲，可暂停”、队列当前项 selected/“正在播放”、下一项“即将播放”，以及 disabled/loading 状态。
- 触摸目标、contentDescription、stateDescription、标准 selected/disabled/adjustable 语义和自定义无障碍排序动作存在。

### 14.3 视觉与适配

- 深色、浅色关键文本和图标对比度满足目标。
- 至少验证 320×568、360×800、宽度 600dp 和视频横屏；字体覆盖 1.0、1.3、2.0 倍。
- 三键导航、手势导航、刘海/圆角安全区和设置页 IME 打开状态下无主操作不可达。
- 状态栏、导航栏、刘海和手势区域不覆盖内容。
- 首页、浏览、设置、图片、音频、视频、迷你播放器和队列形成同一视觉语言。
- 设备截图基线至少包含：首页、浏览、设置、图片、音频、视频普通/全屏、迷你播放器、队列、Dialog，以及 Loading/Empty/Error 状态。
- 使用设备截图进行人工视觉复核；若当前工具链没有稳定截图回归基础设施，不为本轮引入重量级平台。

### 14.4 媒体与后台

- 暂停后播放音画同步。
- 暂停拖动后保持暂停，播放从目标位置继续。
- UI 时间与引擎实际时间保持既定容差。
- 已知有声无画样本能够出画面或显示明确的不支持错误，不无限旋转。
- Home、锁屏和回前台场景符合“后台声音继续、前台画面恢复”。
- 音频焦点永久丢失和耳机/蓝牙断开时暂停且不擅自恢复。

### 14.5 发布

- 完整本地门禁通过。
- APK 只含 `arm64-v8a`。
- 输出 APK 绝对路径、大小、版本、签名用途限制和 SHA-256。
- 清楚标注真实服务器、真实问题媒体、锁屏、任务划除等人工场景的 PASS、FAIL 或 NOT RUN。

## 15. 风险与控制

| 风险 | 控制方式 |
|---|---|
| 大范围视觉改造掩盖行为回归 | 先修测试契约和 P0 状态机；按 Wave 小提交 |
| 主题令牌导致浅色对比度问题 | 对比度计算 + 浅/深色设备截图 |
| Scaffold 重构影响 inset 和返回 | 页面级 Compose 测试 + 小屏/横屏设备检查 |
| 播放器重组破坏后台或 Surface | 保持 Service/Engine 边界；运行已有后台和输出测试 |
| 队列拖动扩大持久化回归 | 先纯状态排序测试，再 Compose 拖动，再 Room 集成 |
| 冷恢复测试难以完全自动化 | 状态机/JVM 覆盖与设备流程结果分开记录 |
| 范围过大 | 固定非目标；每个 Wave 达到完成定义后再继续 |

## 16. 完成定义

本次任务只有同时满足以下条件才可标记完成：

1. 设计系统和共享原生组件已用于所有在范围页面。

3. 审计中 P0/P1 主流程问题已修复，或有明确证据证明不成立。
4. 全流程 Bug 矩阵已执行，未执行项被明确标记且不伪装通过。
5. 自动化门禁、可用设备测试和独立代码评审完成。
6. 最终 arm64-v8a Release APK、校验和和验收报告可交付。
