# 播放进度时钟修复与播放器控件分层布局设计

日期：2026-08-02  
状态：已通过对话确认，待用户审阅文档

## 1. 背景

当前 Android 播放器在暂停后恢复播放时，媒体画面和声音仍按正常速度播放，但底部时间数字和进度滑块明显跑得过快。该现象说明问题位于进度显示链路，而不是解码速度或播放速度设置。

普通视频、全屏视频和音频页面的功能按钮也需要按使用频率重新分层，降低按钮拥挤和误操作，同时保留已经确认并实现的菜单、手势、半透明功能区、自动隐藏和异形屏适配行为。

本次采用定向修复和共享控件重排，不重写 MediaSessionService、LibVLC 引擎、播放队列或播放器状态机。

## 2. 已确认的设计选择

- 进度异常只表现为时间数字和进度滑块加速，视频画面与声音没有加速。
- LibVLC 上报的绝对播放位置是唯一可信进度来源。
- Media3 服务播放器不能在 LibVLC 位置快照上再次生成独立的递增时钟。
- 控件布局采用 A 方案“按使用频率分层”，同时改造普通视频、全屏视频和音频页面。
- 播放/暂停是视觉和交互优先级最高的主操作。
- 普通视频的速度、播放模式和画面比例继续收纳在右上角“更多”菜单。
- 全屏视频的速度、播放模式和画面比例继续显示在进度条下方；右上角“更多”菜单只保留后台播放复选框。
- 音频页面复用共享传输控件，但不加入画面比例、全屏、锁定等视频专属功能。
- 审查范围保持为基础功能性审查；测试执行中只重验未通过的项目。

## 3. 目标与非目标

### 3.1 目标

- 修复暂停后恢复播放时 UI 进度跑得过快的问题。
- 确保暂停期间 UI 进度保持不动，恢复后与 LibVLC 实际位置一致。
- 保持拖动预览、seek 提交和实际位置回归之间的既有边界。
- 让普通视频、全屏视频和音频页面形成一致、清晰的控件层级。
- 保留单击显隐、双击播放/暂停、自动隐藏、半透明背景和安全区适配。
- 用定向自动化测试和基础功能检查防止进度与布局回归。

### 3.2 非目标

- 不改变媒体实际播放速度和播放速度选项。
- 不重写 LibVLC 与 Media3 的服务架构。
- 不重新准备媒体，不重建队列，不改变暂停恢复视频输出的现有修复顺序。
- 不增加字幕、多音轨、投屏、画中画或新的播放模式。
- 不改变后台播放默认关闭和会话级生效的规则。
- 不为控件重排引入新的重量级设计系统或第三方依赖。
- 不对与本次进度和控件布局无关的页面做视觉重构。

## 4. 进度异常根因与数据流

### 4.1 现有数据流

```text
LibVLC TimeChanged 事件
        ↓
AndroidVlcPlaybackEngine / PlaybackState.positionMs
        ↓
PlaybackCoordinator / VlcSessionPlayer
        ↓
MediaSession / MediaController.currentPosition
        ↓
Media3PlaybackController（约 250 ms 读取）
        ↓
PlayerViewModel / PlaybackTimeline
```

Compose 时间轴没有自行运行的动画，它展示的是控制器提供的位置。问题发生在服务侧将 LibVLC 的绝对位置交给 Media3 时：Media3 在满足“正在播放、已就绪”等条件后，会把位置值转换成可按时间和播放速度外推的位置供应器。这样，LibVLC 已经推进的位置又可能被 Media3 继续推算，暂停后恢复的状态切换会放大这一重复计时现象。

### 4.2 单一时钟原则

- `PlaybackState.positionMs` 代表 LibVLC 最近一次确认的绝对位置。
- `VlcSessionPlayer` 向 Media3 公布位置时必须使用常量位置快照，或使用能够保证同等语义的实现。
- Media3 不得基于该快照额外外推服务播放器的位置。
- 现有状态事件和约 250 ms 的控制器读取继续负责把新快照送到 UI。
- Compose 只展示实际快照或用户正在拖动的预览值，不建立第三套进度时钟。

## 5. 进度修复行为

### 5.1 正常播放与暂停恢复

- 正常播放时，每次收到 LibVLC 新位置后更新服务状态和 UI。
- 暂停后保持最后确认位置，不随系统时钟继续递增。
- 再次播放但尚未收到新位置事件时，UI 仍显示最后确认位置。
- 收到恢复后的新位置事件时，时间数字和滑块一次更新到该绝对位置。
- 不调整 LibVLC 播放速率，也不改变 `play()` 与视频输出刷新之间已经生效的顺序。

### 5.2 拖动和 seek

- 用户拖动进度条时，时间文本和滑块显示拖动预览值。
- 松手时只提交一次 seek。
- seek 确认前继续沿用现有目标位置保护，避免旧事件把滑块拉回。
- seek 确认后重新以 LibVLC 的实际位置为准。
- 暂停状态下 seek 后仍保持暂停，恢复播放时不额外推算位置。

### 5.3 边界值

- 已知总时长时，显示位置限制在 `0..durationMs`。
- 总时长未知或无效时，不利用本地计时器伪造总时长或位置。
- 媒体切换、播放结束和错误状态继续清理旧媒体的拖动或 seek 临时状态。
- 播放速度不是 `1.0x` 时仍只接受 LibVLC 上报的绝对位置，不能由 UI 或 Media3 再乘一次速度。

## 6. 普通视频控件布局

普通视频使用完整竖屏可用画布计算画面比例，功能区作为半透明浮层覆盖在视频上，不改变视频 Surface 尺寸。

### 6.1 顶部功能区

- 左侧：返回。
- 中间：当前视频标题，可按现有规则截断。
- 右侧：“更多”。
- “更多”菜单依次提供后台播放复选框、播放速度、播放模式和画面比例。
- 后台播放每次进入新视频会话默认不选中。

### 6.2 底部功能区

从上到下分为三层：

1. 时间轴层：进度滑块、当前时间、总时长。
2. 高频传输层：上一项、后退 10 秒、放大的播放/暂停或重播按钮、前进 10 秒、下一项。
3. 工具层：播放列表和音量组成一组，全屏按钮位于右侧并与工具组保持清晰间隔。

播放/暂停按钮尺寸和容器强调级别最高；其他按钮保持足够触控尺寸，但不与主操作争夺视觉中心。

## 7. 全屏视频控件布局

### 7.1 顶部功能区

- 左侧：返回或退出当前播放器页面的既有入口。
- 中间：当前视频标题。
- 右侧：“更多”。
- “更多”菜单只显示后台播放复选框。

### 7.2 中央传输区

- 后退 10 秒。
- 放大的播放/暂停或重播按钮。
- 前进 10 秒。

中央传输区只在功能区显示时出现，不长期遮挡画面。

### 7.3 底部功能区

从上到下分为三层：

1. 时间轴层：进度滑块、当前时间、总时长。
2. 播放配置层：播放速度、播放模式、画面比例，以紧凑选项显示。
3. 工具层：上一项、下一项和播放列表组成一组；音量、锁定和退出全屏组成另一组。

全屏布局不得把队列按钮重新塞回顶部，也不得把速度、模式和比例重新收入“更多”菜单。

## 8. 音频控件布局

音频页面复用时间轴和传输控件的分层原则：

1. 时间轴层：进度滑块、当前时间、总时长。
2. 高频传输层：上一项、后退 10 秒、放大的播放/暂停或重播按钮、前进 10 秒、下一项。
3. 工具层：播放速度和播放模式组成一组；播放列表和音量组成一组。

音量按钮继续打开既有音量交互。音频页面不显示画面比例、全屏、锁定、视频后台播放复选框或其他视频专属控件。

## 9. 共同交互与视觉规则

- 单击视频画面切换上下功能区显示或隐藏。
- 双击视频画面只切换播放/暂停，不额外触发单击显隐。
- 菜单、按钮和时间轴优先消费自己的事件，不能透传给视频手势层。
- 有效控件操作后重新计算自动隐藏时间。
- 自动隐藏继续使用设置页的 `3 秒 / 5 秒 / 10 秒 / 15 秒 / 不隐藏`。
- 上下功能区使用半透明深色背景或渐变，保证文字可读并减少画面遮挡。
- 必要按钮、文字、时间轴和菜单避开 `WindowInsets.safeDrawing`，视频背景仍可延伸到窗口边缘。
- 控件的 `contentDescription`、测试语义和禁用状态随重排保留，不能只追求视觉位置。
- 普通与全屏模式共享同一播放会话；切换模式不能重置位置、速度、模式、比例、队列或后台播放开关。

## 10. 组件与职责边界

- `VlcSessionPlayer` 负责把 LibVLC 位置以不可重复外推的快照形式公布给 Media3。
- `Media3PlaybackController` 继续按现有节奏读取控制器状态，不新增 UI 递增任务。
- `PlayerViewModel` 继续组合播放状态、拖动预览和页面交互，不承担真实时钟推进。
- `PlaybackTimeline` 只负责时间轴显示和 seek 交互。
- 普通视频与音频优先复用共享的时间轴、传输按钮和工具按钮组件。
- 全屏视频可使用专门布局，但按钮命令必须复用同一控制器行为。
- 视频专属菜单、画面比例、锁定和全屏逻辑不得进入音频组件。

## 11. 错误处理

- 位置事件小于零时按零处理；超过已知总时长时限制到总时长。
- 位置或时长暂时不可用时保留最近有效快照，不启动本地补偿计时。
- seek 失败时回退到播放器实际位置，并沿用现有轻量错误反馈。
- 媒体错误不能留下仍在自行递增的 UI 位置。
- 控件重排不得吞掉按钮点击、手势事件或自动隐藏重置事件。
- 暂停恢复画面刷新失败的处理保持现有边界，不通过重载媒体来掩盖进度问题。

## 12. 测试与验收

### 12.1 进度单元测试

先增加能够稳定复现问题的失败测试，再修改生产代码：

1. 模拟 LibVLC 在已知位置暂停。
2. 恢复播放，但暂不发送新的 `TimeChanged` 事件。
3. 推进测试时钟，断言 Media3 公布的位置没有自行快进。
4. 发送新的绝对位置事件，断言控制器与 UI 状态精确更新到该位置。

同时覆盖：

- 连续多轮暂停和恢复不累积额外进度；
- `2.0x` 等非默认速度不会让显示位置被重复乘速；
- 暂停 seek 后保持目标位置，恢复后接受新的实际位置；
- 媒体切换、结束和错误后不保留旧位置时钟。

### 12.2 Compose 布局测试

- 普通视频顶部“更多”包含后台、速度、模式和比例，底部三层按钮顺序正确。
- 全屏“更多”只包含后台，速度、模式和比例位于进度条下方。
- 全屏中央只提供后退、播放/暂停、前进三个主操作。
- 音频页面具有共享传输按钮，但不存在视频专属控件。
- 三种页面的播放/暂停按钮均保持最高视觉和语义优先级。
- 单击、双击、自动隐藏和控件事件消费没有因重排回归。
- 注入顶部、左右和底部安全区后，必要控件仍可见且可操作。

### 12.3 基础功能检查

- 使用一个视频样本执行播放、暂停、等待、恢复和 seek，确认画面/声音与时间轴同步。
- 分别查看普通视频、全屏视频和音频页面，确认按钮分组、菜单内容和半透明背景。
- 检查 3、5、10、15 秒及“不隐藏”的既有设置没有回归。
- 执行定向 JVM/Compose 测试和相关 Android 构建检查。
- 测试执行中只重验未通过的项目，不重复已通过项目，不增加与本次范围无关的全面审查。
- 若没有可用设备，真机交互项明确记录为 `NOT RUN`，不能用编译通过代替。
- 代码通过相关验证后，重新构建仅包含 `arm64-v8a` 的 Release APK，并记录路径、大小、SHA-256 和签名验证结果。

## 13. 基础功能性审查范围

只检查：

1. 规格和实现是否存在占位符、需求遗漏、明显矛盾或越界改动；
2. 进度是否只有一个可信时钟，暂停恢复是否存在重复推进；
3. 普通视频、全屏视频和音频按钮是否符合已确认分层；
4. 既有菜单、手势、自动隐藏、半透明背景和安全区行为是否明显回归；
5. 定向测试、相关构建和 APK 产物验证是否有新鲜证据。

不增加独立多轮评审、全仓架构审计、重量级视觉审查或与本次修改无关的测试扩展。

## 14. 完成定义

本次任务完成必须同时满足：

1. 暂停后恢复播放时，时间数字和进度滑块不再快于实际媒体。
2. 暂停期间位置保持不动；恢复后显示值来自 LibVLC 新位置事件。
3. 普通视频、全屏视频和音频页面按 A 方案完成分层重排。
4. 菜单内容、单击/双击、自动隐藏、半透明背景和异形屏适配没有回归。
5. 进度失败测试先红后绿，相关布局测试和构建检查通过。
6. 未执行的真机项被明确标记，不以静态或编译结果代替。
7. 更新后的 `arm64-v8a` Release APK 完成校验并可供交付。
