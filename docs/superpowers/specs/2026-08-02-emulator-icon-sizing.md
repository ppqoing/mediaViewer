# Android 模拟器图标尺寸调整设计

## 背景

在 API 36、Pixel 3a（1080×2220、440 dpi）模拟器上，对首页、设置、目录浏览、空目录、视频控制、播放队列、图片/漫画、GIF 和音频播放器进行了逐页截图。文件类型图标、空状态图标和主播放按钮比例正常，但以下图标明显偏大：

- 顶部搜索、刷新、返回、更多操作；
- 首页行尾箭头、目录面包屑分隔箭头；
- 设置页服务器 URL 前导图标；
- 迷你播放条的播放、下一项、队列按钮；
- 播放队列标题栏的更多与关闭按钮；
- 图片查看器的模式、翻页、缩放和适合屏幕按钮；
- 视频与音频播放器的非主操作按钮。

## 根因

本套图标均为 `drawable-nodpi` 下的 192×192 PNG，图形主体约占画布边长的 70%–74%。部分 `MediaIconImage` 调用没有显式尺寸，因而会按资源固有尺寸或父组件最大约束参与测量；`MediaIconButton` 只保证了 48dp 最小触摸区域，没有限制内部图标尺寸。结果是触摸区域和视觉图标几乎一样大，主次层级失衡。

## 方案

采用按使用场景分级的尺寸方案，不裁切或重新生成 PNG：

| 场景 | 图标画布尺寸 | 说明 |
|---|---:|---|
| 普通页面操作按钮 | 28dp | 搜索、刷新、返回、更多、关闭、网格等 |
| 播放器次级控制 | 32dp | 上一项、下一项、快退/快进、队列、音量、全屏、图片翻页和缩放 |
| 行内与分隔图标 | 20–24dp | 面包屑、行尾箭头、输入框前后图标 |
| 文件类型与分段控件 | 保持现状 | 文件/文件夹徽标、筛选项、图片/动图/漫画分段 |
| 主播放按钮 | 保持现状 | 继续使用 64dp 主按钮和 32dp 图标 |
| 空状态与音频封面 | 保持现状 | 不改变当前视觉强调层级 |

所有可点击图标继续保留至少 48dp 的触摸目标，仅收紧内部图形，不降低可访问性。

## 组件接口

- `MediaIconButton` 新增 `iconSize: Dp = 28.dp`。
- `PlayerIconButton` 新增 `iconSize: Dp = 32.dp`。
- 两者继续使用 `MediaTheme.sizing.minimumTouchTarget` 保证触摸区域。
- 直接使用 `MediaIconImage` 的位置必须显式传入 `Modifier.requiredSize(...)`，强制视觉尺寸不受父级最小触控约束放大；不修改 `MediaIconImage` 的全局默认值，避免影响封面、空状态和主按钮。

## 验收标准

1. 普通操作按钮的可点击区域仍不小于 48dp。
2. 默认普通按钮的可见图形不超过约 24dp；播放器次级按钮不超过约 28dp。
3. 面包屑不再被大箭头撑高或挤压文字。
4. 首页、设置、浏览、空目录、视频、队列、图片、GIF、音频页面重新截图后，不再出现抢占文字或容器的图标。
5. 主播放按钮、文件类型徽标、空状态、音频封面和分段控件保持当前层级。
6. 相关单元测试、Compose UI 测试及 Debug 构建通过。
